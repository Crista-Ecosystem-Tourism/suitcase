# Инструкция по сборке APK и работе с Firebase

Эта инструкция описывает два основных процесса: применение настроек безопасности/базы данных в Firebase и локальную генерацию релизных APK-файлов с инкрементом версий.

---

## 1. Сборка новой версии APK

Я подготовил скрипт `build_apk.sh`, который автоматически:
1. Настраивает нативный Android-проект (`npx expo prebuild`), если его нет.
2. Запускает `gradle` сборку.
3. Копирует готовый APK в папку `versions/` и автоматически увеличивает цифру в названии (например, `green_suitcase_v1.apk`, `green_suitcase_v2.apk` и т.д.).
4. **Важно:** Автоматически удаляет за собой все временные папки сборки (`android`, `ios`, `dist`), оставляя дерево проекта чистым.

### Команда для запуска сборки:
```bash
./build_apk.sh
```

> **Примечание:** Убедитесь, что у вас установлены Android Studio и Java (JDK 17). Если при сборке `gradlew` будет ругаться на права доступа, дайте ему права на исполнение: `chmod +x android/gradlew` (скрипт постарается всё сделать сам, но иногда права сбрасываются).

## 2. Обновление (Деплой) базы данных Firebase

Поскольку приложение работает с Firestore (БД), вам нужно убедиться, что в Firebase настроены правила безопасности (Security Rules) и индексы (Indexes, если они потребуются для сложных сортировок).

### Если `firebase-cli` еще не установлен:
```bash
npm install -g firebase-tools
```

### Авторизация в аккаунте Google:
```bash
firebase login
```

### Инициализация проекта (нужно сделать 1 раз):
В корне вашего проекта выполните команду и выберите ваш проект (`green-suitcase`):
```bash
firebase init firestore
```
*На вопросы CLI отвечайте `Enter` (по умолчанию он создаст файлы `firestore.rules` и `firestore.indexes.json`).*

### Пример правильных `firestore.rules`:
В созданном файле `firestore.rules` пропишите базовую безопасность (каждый пользователь видит только свои данные):
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      // Разрешаем чтение и запись только если пользователь авторизован и это его папка
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

### Команда для применения (деплоя) изменений в Firebase:
Как только вы изменили правила или индексы, отправьте их на сервер:
```bash
firebase deploy --only firestore
```

---

## 💡 Типичный воркфлоу разработки:

1. Вы пишете код, меняете экраны.
2. Проверяете в симуляторе (через `npx expo start`).
3. Если поменяли структуру базы, обновляете `firestore.rules` и делаете:
   `firebase deploy --only firestore`
4. Когда всё готово и проверено, собираете свежий APK для телефона:
   `./build_apk.sh` 
5. Отправляете файл из папки `versions/` на телефон.
