# 🚀 Инструкция по сборке и разработке

Этот документ описывает процесс локальной разработки и генерации релизных сборок (Android, iOS, Web) с автоматическим версионированием.

## ⚠️ Важное предупреждение!
**В этом проекте запрещено использовать `pnpm` (или `yarn`).** 
Используйте только `npm`, так как многие нативные зависимости и скрипты `npm install --legacy-peer-deps` чувствительны к менеджеру пакетов. Смешивание менеджеров или файл `pnpm-lock.yaml` сломает сборку нативных модулей.

---

## 📱 Локальная разработка

Для запуска проекта в режиме разработчика (с Hot Reload):
```bash
npx expo start
```
*Затем вы можете нажать `i` для запуска iOS симулятора, `a` для Android эмулятора, или `w` для веб версии.*

## 📦 Скрипты для сборок (Build Scripts)

В проекте настроены три скрипта для автоматической сборки приложения под разные платформы.
Все скрипты автоматически сохраняют историю сборок в папку `versions/` с увеличением версии (v1, v2, v3 и т.д.).

### 1. Сборка Android (APK)

Команда для запуска:
```bash
./build_apk.sh
```
**Что делает скрипт:**
- Проверяет наличие зависимостей (папки `node_modules` и пакета `expo`) и устанавливает их при необходимости.
- Удаляет конфликтующие папки от iCloud (`.expo 2` и т.д.).
- Всегда синхронизирует Android нативный проект (`CI=1 npx expo prebuild --platform android`).
- Запускает `./gradlew clean assembleRelease` для создания релизного `.apk`.
- Копирует готовый файл в папку `versions/android_versions/` под именем `suitcase_vX.apk`.
- Пытается автоматически установить APK на запущенный эмулятор или подключенное устройство через `adb`.
- Сохраняет сгенерированную папку `android` (используется кэш для 10-кратного ускорения последующих сборок).

### 2. Сборка iOS (.app)

Команда для запуска:
```bash
./build_ios.sh
```
**Что делает скрипт:**
- Проверяет наличие зависимостей (папки `node_modules` и пакета `expo`) и устанавливает их при необходимости.
- Удаляет конфликтующие папки от iCloud.
- Всегда синхронизирует iOS нативный проект (`npx expo prebuild --platform ios`).
- Подтягивает нативные зависимости (`pod install`).
- Запускает `xcodebuild` для компиляции Release-приложения под симулятор.
- Если сборка падает на `CodeSign` из-за `resource fork / FinderInfo`, скрипт автоматически:
  - пересобирает `.app` без xattr через `ditto --noextattr --norsrc`,
  - удаляет проблемные xattr,
  - и подписывает приложение вручную для симулятора.
- Архивирует готовую `.app` директорию в `tar.gz` (чтобы сохранить файловую структуру и права) и кладет в `versions/ios_versions/suitcase_vX.tar.gz`.
- Перед установкой проверяет, запущен ли симулятор:
  - если уже запущен — не перезапускает его;
  - если не запущен — запускает автоматически и ждёт готовности.
- Затем удаляет старую версию приложения и устанавливает новую через `xcrun simctl`.
- Оставляет папку `ios` для быстрого инкрементального билда в будущем.

### 3. Веб-версия

Веб-версия Suitcase собрана **в основном фронтенде Crista** (`frontend/`, раздел «Мой чемодан» в сайдбаре). Отдельной сборки и Firebase Hosting больше нет — данные едут в общий бэкенд `ai_agent` (`/suitcase/*`).

## 🔌 Подключение к Crista API

Мобильное приложение хранит данные и аутентификацию в собственном бэкенде Crista (PostgreSQL + JWT), а не в Firebase. URL API задаётся через `app.json → expo.extra.apiUrl` (по умолчанию `https://api.crista.online`) или переменную `EXPO_PUBLIC_API_URL`.

Регистрация/логин: email + пароль через `/auth/register` и `/auth/login`. Токен хранится локально в `AsyncStorage`.

## 🧹 Устранение неполадок (Troubleshooting)

Если при нативной сборке возникают странные ошибки плагинов, кэша или зависимостей:
1. Запустите глубокую очистку:
   ```bash
   rm -rf android ios node_modules dist .expo .expo-shared
   ```
2. Переустановите `node_modules`:
   ```bash
   npm install --legacy-peer-deps
   ```
3. Запустите нужный скрипт сборки заново. Он с нуля создаст нативные проекты.
